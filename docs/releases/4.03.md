# zQuoridor 4.03 — Unified Lazy and clock-budget correctness

Release: **20 October 2026**. Production search: **Lazy Expansion + exact Sparse Policy at every time control**. The original 858-feature / 512-hidden / 209-policy-logit NNUE weights remain unchanged from version 4.01. **Apex Policy25 is not part of this release.**

## Behavior

The UCI protocol does not classify fixed `movetime` and clock-based `wtime/btime` into different expansion algorithms. Both use Lazy+Sparse. On real clocks, `src/time_manager.hpp` derives the budget from time remaining, Fischer increment, ply and overhead, while the Adaptive Time manager may spend more on volatile roots. On fixed move time, Adaptive Time is disabled by default. The search graph can be reused when the GUI switches protocol without resetting its expansion scheme.

### Timing fix

Before 4.03, the MCGS search clock started after policy history seeding, rerooting, compaction and root graph preparation. These steps could be expensive with very large reused trees. 4.03 starts the tree-phase clock **before** preparation, after any optional AB pre-ranking whose measured wall time is already subtracted from the move allocation. Both adaptive stop logic and leaf deadlines refer to the same earlier timestamp. This avoids charging prep time twice or omitting it.

### Diagnostics

`--eager-search` is an explicit opt-out used for paired A/B comparisons only; it is not selected automatically based on time control. The optional `ponder clock movetime N` syntax is retained as a compatibility hint, but has no effect on the production expansion mode.

## Verification and limits

Local pre-release test results from prior investigation, no pondering:

- 1+1 fresh 4 roots: 4/4 moves equal between Lazy and Eager, Lazy +22.3% simulations.
- 3+2 fresh 4 roots: 3/4 moves equal, Lazy +23.4% simulations; one central wall move differs and has no established objective winner.
- 3+2 reroot case: preparation-inclusive timing reduced a 9.13s wall time to 8.12s for Lazy, without changing the chosen move.
- 5+3 same-root case: preparation-inclusive timing reduced a 13.93s wall time to 13.22s for Lazy.
- Fixed 500ms 36 roots: 36/36 same moves with the original policy; 500ms second-root reuse 8/8.
- New Apex weights were explored in a **separate** experimental investigation but are excluded from 4.03; no Apex weight or artifact is bundled.

These are **efficiency and correctness observations** and do not certify competitive 3+2 or 5+3 Elo superiority. The 4.03 native+WASM release gate separately builds original production model, tests engine modes and verifies embedded bytes in both standalone HTMLs. No large tournament is part of this release gate.
