# Experiment: Bilateral Value Head v2

## Status

**Training complete. Wandering regression passed. Elo arena pending rerun because the first arena failed before game 1 due to a missing local Git ref in the CI worktree setup.**

## Hypothesis

The previous WL head receives only the side-to-move accumulator. In wall-poor race states this can make value insensitive to the opponent's relative position and wall inventory. Feeding both canonical player accumulators to the value head should improve race-state discrimination while preserving the existing shared incremental transformer and policy head.

## Change

- Keep the shared sparse transformer at 354 -> 256.
- Keep the policy head unilateral, using the mover accumulator.
- Build and update both quantized accumulators eagerly.
- Change the WL head to `concat(SCReLU(acc_own), SCReLU(acc_opp)) -> 64 -> 1`.
- Use `cPuct = 1.20`, already independently confirmed stronger than 1.50.
- Fix data generation so `evalNNUE` uses both accumulators; the previous compatibility helper duplicated the mover accumulator.
- Fix the float writer to emit all 64 value-hidden units.

## Data and protocol

Teacher data was generated by Gen8 with `cPuct = 1.20`:

- 5,000 games
- 10 V3 shards
- 298,641 positions total
- 4,484 wall-poor/risk positions
- 9 shards / 268,241 positions for training
- 1 shard / 30,400 positions for validation

Training:

- fresh initialization
- 60 epoch maximum, early stopping
- batch 8,192
- LR 3e-4 with existing schedule
- WL gamma 0.995
- wall-poor WL weight 3.0
- visit-policy targets from ply 0
- monitor `val_outcome`

Evaluation protocol:

- incremental accumulator parity test
- wandering regression
- 1,200-game arena vs Gen8 at 20 ms/move, 4 random opening plies
